## One tree, starting at /

On Windows each drive has its own tree (`C:\`, `D:\`). Linux and macOS have **a single tree**. Its top is called the **root directory** and written as a single slash: `/`.

Everything lives somewhere below `/`. An extra disk isn't a new tree; it is **mounted** onto a directory (for example `/mnt/data`) and its contents appear there.

```text
/
├── bin -> usr/bin     essential programs (a link on modern systems)
├── boot               kernel and boot loader
├── dev                device files: disks, terminals, /dev/null
├── etc                system-wide configuration
├── home               users' home directories
│   └── learner        ← your files live here
├── opt                optional, self-contained software
├── proc               live process and kernel information
├── root               the root user's home directory
├── tmp                temporary files, cleared on reboot
├── usr                installed software (bin, lib, share)
│   ├── bin            most user commands: ls, grep, git…
│   └── local          software you installed yourself
└── var                variable data
    ├── log            log files
    └── www            web content (by convention)
```

This layout is standardised by the **Filesystem Hierarchy Standard (FHS)**, so the same directories mean the same things on Ubuntu, Fedora or Debian servers.

## The directories you will use most

| Directory | Holds | You'll use it to… |
|---|---|---|
| `/home/<user>` | Your documents, projects and personal config | Do your everyday work |
| `/etc` | System configuration (text files!) | Configure services: `/etc/ssh/sshd_config`, `/etc/hosts` |
| `/var/log` | Logs from the system and services | Troubleshoot: `/var/log/syslog`, `/var/log/nginx/` |
| `/tmp` | Temporary files, writable by everyone | Scratch space for scripts (use `mktemp`) |
| `/usr/bin`, `/bin` | Programs | Find out where a command lives |
| `/usr/local/bin` | Programs you installed manually | Install your own tools |
| `/opt` | Large third-party applications | Self-contained installs |
| `/dev` | Device files | `/dev/null`, `/dev/sda`, `/dev/tty` |
| `/proc`, `/sys` | Virtual files generated by the kernel | Inspect processes, CPU, memory |

> [!NOTE] Configuration is text
> Almost all Linux configuration lives in plain-text files under `/etc` and in hidden files in your home directory. That's why text tools like `grep`, `sed` and editors are so central — and why configuration can be versioned, diffed and automated.

## Your home directory and ~

Each user has a **home directory**, normally `/home/<name>` (and `/root` for the root user; `/Users/<name>` on macOS). It is the starting directory when you log in and the only place an ordinary user can freely create files.

The shell offers shorthands:

- `~` — your home directory (`/home/learner`)
- `~/projects` — a path inside your home directory
- `~alice` — another user's home directory
- `$HOME` — the variable holding your home path, handy in scripts

```bash
echo ~           # /home/learner
echo ~/notes.txt # /home/learner/notes.txt
cd               # with no argument, cd goes home
```

## Hidden files

Any file or directory whose name starts with a dot (`.`) is **hidden**: `ls` and glob patterns like `*` skip it unless asked. This is a convention, not a security feature — it keeps configuration out of the way.

::terminal
$ ls
$ ls -a
$ cat .bashrc
$ ls -la .ssh
::

Common hidden entries in a home directory:

| Name | Purpose |
|---|---|
| `.bashrc` | Commands run by every interactive Bash: aliases, prompt, functions |
| `.profile`, `.bash_profile` | Run by login shells: environment variables such as PATH |
| `.ssh/` | SSH keys and client configuration (must be private: mode 700) |
| `.config/` | Configuration for many modern applications |
| `.git/` | Inside a project: the Git repository data |

Every directory also contains two special hidden entries: `.` (the directory itself) and `..` (its parent). You'll use them constantly in the next lesson.

## Everything is a file

A core Unix idea is that many things which aren't documents are still accessed *like* files — opened, read and written with the same system calls:

- `/dev/null` — a "black hole": writing to it discards data, reading from it returns nothing.
- `/dev/urandom` — an endless stream of random bytes.
- `/dev/tty` — the terminal the current process is attached to.
- `/proc/<pid>/` — a directory of information about each running process.
- `/proc/cpuinfo`, `/proc/meminfo` — hardware information as text.

```console
$ ls /dev | head -3
null
random
stderr
$ head -c 12 /dev/urandom | base64
yDl0dnZ0Ndc1CGEV
```

This uniformity is why a few generic tools — `cat`, `grep`, redirection — work on so many different things.

## Common mistakes

```mistake
title: Storing work files in /tmp
wrong: |
  cp important-report.csv /tmp/
  # ...after a reboot, it's gone
right: |
  mkdir -p ~/reports
  cp important-report.csv ~/reports/
why: /tmp is cleaned on reboot (and periodically by systemd-tmpfiles). Use it only for short-lived scratch data.
```

```mistake
title: Thinking hidden means secret
wrong: |
  echo "password=hunter2" > ~/.secret   # "nobody can see it"
right: |
  install -m 600 /dev/null ~/.secret     # create it private first
  echo "password=hunter2" > ~/.secret
why: A leading dot only hides the file from `ls`. Access is controlled by permissions; give secrets mode 600.
```

## Practice

```exercise
kind: mcq
difficulty: beginner
prompt: Where would you look for the configuration of the SSH server on a Linux machine?
options:
  - /home/ssh
  - /etc/ssh/
  - /var/ssh
  - /usr/bin/ssh
answer: 1
hints:
  - System-wide configuration has one standard home.
explanation: System configuration lives under **/etc**; the SSH server reads `/etc/ssh/sshd_config`. `/usr/bin/ssh` is the client program itself.
```

```exercise
kind: command
difficulty: beginner
prompt: List **all** entries in your home directory, including hidden ones, in long format.
solution: ls -la ~
hints:
  - Two flags of `ls` — one for long format, one for "all".
  - Flags can be combined into one argument.
explanation: "`ls -la` (or `ls -al`) shows hidden entries such as `.bashrc` and `.ssh`, plus `.` and `..`. Running it in `~` or naming `~` gives the same result."
```

```exercise
kind: command
difficulty: beginner
prompt: The system's host-name lookup table lives in a file called `hosts` in the configuration directory. Print it.
solution: cat /etc/hosts
hints:
  - Which top-level directory holds configuration?
explanation: "`/etc/hosts` maps names to IP addresses before DNS is consulted — useful for testing, and a frequent troubleshooting stop."
```

## Challenge

```exercise
kind: mcq
difficulty: intermediate
prompt: A script writes 20 GB of temporary data to `/tmp` and the server crashes with "No space left on device", even though `/data` has 2 TB free. What is the most likely explanation?
options:
  - Linux can't use more than 20 GB of temporary space
  - "`/tmp` is on a different (small) filesystem — often the root disk or a RAM-backed tmpfs — while `/data` is a separately mounted large disk"
  - Hidden files take extra space
  - The script should have used `~` instead
answer: 1
hints:
  - One tree doesn't mean one disk. How do extra disks appear in the tree?
explanation: "Directories in the single tree can live on different filesystems. `df -h /tmp /data` would show their sizes. Point large scratch work at the big disk, e.g. `TMPDIR=/data/tmp`, which `mktemp` respects."
```
